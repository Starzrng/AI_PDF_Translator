# jobs/ — работы

Здесь лежат переводы: одна папка на один мануал, `jobs/<id>/`. Готовые PDF и исходники в репозиторий не попадают (их хранят локально, см. `.gitignore`), в git — то, из чего PDF собирается заново: переводы, скрипты, глоссарии, заметки.

## Что внутри работы

| Файл | Что это | В git |
|---|---|---|
| `source.pdf` | исходный мануал | нет |
| `job.json` | описание работы для харнесса: исходник, имя результата, режим, правила глоссария | да |
| `blocks.json` | инвентарь текстовых блоков исходника — ключи переводов; после первого перевода не пересоздаётся | да |
| `translations.py` | перевод: по записи `t(...)` на абзац | да |
| `NOTES.md` | статус, команда сборки, решения пользователя, исправленные ошибки оригинала | да |
| `out/` | результат сборки (`*_RU.pdf`), отчёт проверок `qa.json`, геометрия `layout.json` | нет |
| `legacy/` | старая сборка работы, переделанной через харнесс; её переводы читает память переводов | да (кроме PDF) |

Работы, начатые до харнесса, устроены по-своему (`build.py` со своей геометрией, у XM-100 — HTML-вёрстка). Как собрать каждую — в её `NOTES.md`.

Новая работа заводится командами из [README](../README.md#как-перевести-новый-мануал); правила для агента — в [AGENTS.md](../AGENTS.md).
