# PDF Translator

Харнесс для перевода технических PDF (руководства к 3D-принтерам, сканерам, лазерам, ЧПУ) на русский язык с сохранением вёрстки.

Переводит ИИ-агент, а харнесс делает всё остальное: разбирает исходник, подставляет уже сделанные переводы, собирает PDF, сам проверяет результат и показывает агенту, что исправить. Человек вмешивается в трёх местах: одобряет пилот, решает спорные вопросы (термины, нужно ли переводить картинки) и вычитывает итог.

## Что получается на выходе

- Та же страница, что в оригинале: картинки, схемы, таблицы и оформление на своих местах, текст — по-русски.
- Английский текст удаляется из PDF, а не закрашивается: нет белых подложек поверх линий, а поиск и копирование отдают только русский.
- Межстрочный интервал, жирность, цвет и размер выделений берутся из оригинала. Если перевод длиннее, блок занимает свободное место рядом, а не мельчает.
- Каждая сборка проверяется автоматически (см. [Проверки](#проверки)).

Пример на одном и том же мануале (Creality Sermoon P1), метрики `pdft.audit`:

| | Старый движок (закрашивание) | Харнесс |
|---|---|---|
| Английский текст, оставшийся в PDF под заливкой | 290 фрагментов | 0 |
| Сжатый текст (< 85 % кегля оригинала) | 34 | 0 |
| Текст поверх графики | 8 | 0 |
| Испорченная графика | 236 pt² | 0 |

## Как это устроено

```
inspect ─► init ─► перевод абзацев ─► build ─► QA ── ошибки ──┐
                         ▲                       │             │
                         └──────── правка ◄──────┘◄────────────┘
                                                 │ 0 ошибок
                                                 ▼
                                      review (пары «оригинал | перевод») ─► человек
```

Харнесс — это всё, что окружает агента:

| Часть | Что это | Где |
|---|---|---|
| Правила | порядок работы, запреты, правила перевода | [`AGENTS.md`](AGENTS.md), [`docs/translation-conventions.md`](docs/translation-conventions.md) |
| Инструменты | команды вместо ручной вёрстки | `python -m pdft …` |
| Проверки | что не так — без участия человека | `pdft/qa.py` → `out/qa.json` |
| Память | уже принятые решения: переводы прошлых работ, глоссарии | `pdft/tm.py`, [`docs/glossary/`](docs/glossary/) |
| Человек | пилот, спорные термины, итоговая вычитка | `NOTES.md` работы |

Главный принцип: каждая правка, которую человек делает повторно, становится правилом, записью в памяти или проверкой. Подробнее — [`docs/harness.md`](docs/harness.md).

## Установка

Нужны Python 3.10+ и шрифт с кириллицей (по умолчанию Arial из macOS).

```bash
git clone https://github.com/Starzrng/pdf-translator.git
cd pdf-translator
python3 -m venv .venv
.venv/bin/pip install -e .
```

На другой системе укажите шрифты: `PDFT_FONT_REGULAR=/path/Arial.ttf PDFT_FONT_BOLD=/path/Arial-Bold.ttf`.

Версия PyMuPDF зафиксирована (1.28.2): от неё зависит разбиение страницы на блоки, а значит, и ключи переводов.

## Как перевести новый мануал

Все команды — из корня репозитория. Ниже `jobs/<id>` — папка работы, например `jobs/sermoon-p1s`.

### 1. Завести работу

```bash
mkdir -p jobs/<id>
cp ~/Downloads/manual.pdf jobs/<id>/source.pdf
.venv/bin/python -m pdft inspect jobs/<id>
```

`inspect` показывает, с чем предстоит иметь дело:

```
jobs/sermoon-p1s/source.pdf: 23 pages, 595×397 pt
  subset fonts: translated text goes in Arial (subsets lack Cyrillic)
vector-heavy pages (labels sit on line art): [3, 4]
raster below 200 dpi (redraw candidates): ['p23 xref250 168×168 → 190 dpi', …]
segments: 217; translation memory: 55 exact, 43 close (≥75 %)
```

По этому отчёту принимается решение, нужно ли переводить картинки ([правило](docs/translation-conventions.md#картинки-и-интерфейс-когда-переводить)). Решение записывается в `jobs/<id>/NOTES.md`.

### 2. Создать каркас перевода

```bash
.venv/bin/python -m pdft init jobs/<id>
```

`init` создаёт `blocks.json` (инвентарь текста), `job.json` и `translations.py`. В каркасе:
- строки уже склеены в абзацы;
- ячейки таблиц разделены;
- у каждого абзаца — английский оригинал с разметкой выделений;
- если такой текст уже переводился в другой работе, перевод подставлен из памяти.

```python
# P5b2 +3  sz6.0 B  (53.9, 95.2, 542.1, 130.1)
# EN: Due to transportation safety regulations, … <b>Please charge the battery for at least 30 minutes …</b>
t('P5b2', merge=['P5b3', 'P5b4', 'P5b5'], html=TODO)

# P5b12  sz6.0  (43.1, 228.0, 119.3, 236.0)
# EN: Complete First-Time Setup
t('P5b12', html='Завершите первоначальную настройку')  # TM exact: sermoon-p1s P5b12
```

Задача переводчика — заменить каждый `html=TODO` на перевод. `init` можно запускать повторно, готовые переводы сохраняются.

### 3. Пилот

Переведите 2–4 характерные страницы (сплошной текст, таблица, схема), затем соберите и посмотрите их:

```bash
.venv/bin/python -m pdft build  jobs/<id> --pages 2,3,5,20
.venv/bin/python -m pdft review jobs/<id> --pages 2,3,5,20     # → tmp/<id>/review_pN.png
```

Пилот показывают человеку; дальше — только после его одобрения.

### 4. Полный перевод

Заполните остальные абзацы и собирайте, пока проверка не покажет ноль ошибок:

```bash
.venv/bin/python -m pdft build jobs/<id>
```

```
saved jobs/sermoon-p1s/out/sermoon-p1s_RU.pdf
QA sermoon-p1s: 0 errors, 1 warnings → jobs/sermoon-p1s/out/qa.json
  p19 WARN  shrunk   P19b7       text at 88% size; grew right 28.0pt (all free space), still shrunk
```

Каждое предупреждение либо исправлено (короче формулировка, сдвиг рамки), либо объяснено в `NOTES.md`.

### 5. Просмотр и сдача

```bash
.venv/bin/python -m pdft review jobs/<id>      # все страницы
```

Просматривается каждая страница. Готовый файл — `jobs/<id>/out/<id>_RU.pdf`, статус — в `NOTES.md`.

## Формат перевода

`translations.py` — обычный Python, чтобы были комментарии и было удобно править:

```python
t('P3b10.1', html='Лазер параллельных линий')              # часть блока (ячейка, одна из двух подписей)
t('P5b2', merge=['P5b3', 'P5b4'], html='…<b>…</b><br>…')    # абзац из нескольких строк
t('P19b0', html='<span style="font-size:7px"><b>3.1 …</b></span><br>…')   # заголовок крупнее текста
t('P4b8', align='center', html='Салфетка для очистки × 1') # явное выравнивание
keep('P20b2')                                              # оставить исходный текст как есть
op(3, (100, 200, 180, 210), 'Текст', size=6)               # текст в явном прямоугольнике
```

Поддерживается HTML: `<b>`, `<br>`, `<span style="color:…; font-size:…">`. Необязательные параметры (`size`, `lh`, `dx0/dy1`, `x0/x1`, `grow`, `paint` и др.) описаны в [`pdft/job.py`](pdft/job.py) и [`docs/overlay-technique.md`](docs/overlay-technique.md). Если не задано иначе, размер, цвет, жирность, интервал и выравнивание берутся из оригинала.

`job.json` — описание работы:

```json
{
 "source": "source.pdf",
 "output": "out/sermoon-p1s_RU.pdf",
 "mode": "overlay",
 "overlay": {"lh": 1.25, "grow": true},
 "rules": ["docs/glossary/creality-scanners.rules.json"]
}
```

## Проверки

После каждой сборки выполняется `qa`. Ошибки блокируют сдачу, предупреждения требуют решения.

| Уровень | Проверка | Что ловит |
|---|---|---|
| ERROR | `todo` | абзац ещё не переведён |
| ERROR | `leftover` | на странице остался текст оригинала |
| ERROR | `moved` | текст оригинала сдвинулся при удалении соседнего блока |
| ERROR | `lost` | удаление задело текст, который должен был остаться |
| ERROR | `truncated` | часть перевода не попала на страницу (MuPDF обрезает переполнение молча) |
| ERROR | `glyph` | символ, которого нет в шрифте (станет пустым квадратом) |
| ERROR | `style` | запрещённый вариант из глоссария («филамент», «останов», …) |
| WARN | `shrunk` | текст пришлось уменьшить ниже 90 % |
| WARN | `text-art` | перевод лёг на линии, иконки или фото |
| WARN | `overlap` | два перевода наложились (если в оригинале рамки не пересекались) |
| WARN | `emphasis` | жирный/цвет, которого нет в оригинале этого абзаца |
| WARN | `fill-art` | закрашенная подложка задевает графику (только для `paint=True`) |

## Другие инструменты

```bash
.venv/bin/python -m pdft.audit source.pdf translated.pdf   # метрики любого перевода, в т. ч. чужого
.venv/bin/python -m pdft.diff old.pdf new.pdf              # попиксельное сравнение двух сборок
.venv/bin/python -m pdft.render file.pdf 3-7               # PNG страниц в tmp/render/
.venv/bin/python -m pdft.blocks jobs/<id>/source.pdf       # инвентарь блоков (только для новой работы)
```

`pdft.diff` нужен при любом изменении кода: прежние работы должны собираться с `max diff: 0.000%`.

## Режимы

| Режим | Когда | Образец |
|---|---|---|
| Оверлей через харнесс | текст извлекается, перевод помещается рядом с оригиналом (обычно EN→RU) | `jobs/sermoon-p1s`, `jobs/sermoon-p1` |
| Пересборка PyMuPDF | страницы проще собрать заново, иллюстрации с легендами | `jobs/falcon2-pro` |
| HTML → Chromium | перевод заметно длиннее оригинала (ZH→RU), нужны новая нумерация страниц, оглавление, перерисованные экраны | `jobs/xm100` |
| Веб-статья | источник — страница сайта, результат — `.md` с картинками | `articles/` |

Харнесс (`python -m pdft`) сейчас ведёт оверлей-работы; остальные режимы собираются скриптами своих работ (команды — в их `NOTES.md`).

## Правила перевода и глоссарии

- [`docs/translation-conventions.md`](docs/translation-conventions.md) — решения пользователя: «пластик», «остановка», когда кнопки пишутся «English (Русский)», когда переводить скриншоты и картинки.
- [`docs/glossary/`](docs/glossary/) — глоссарии по семействам продуктов. Отвергнутые варианты записываются в `<семейство>.rules.json` и подключаются в `job.json`; тогда проверка ловит их сама.
- `jobs/<id>/NOTES.md` — решения конкретной работы и исправленные ошибки оригинала.

## Работа с ИИ-агентом

Правила для агента — [`AGENTS.md`](AGENTS.md): единственный источник, `CLAUDE.md` подключает его, `.hermes.md` — ссылка на него. Агенту достаточно открыть репозиторий: правила, глоссарии, память переводов и проверки дают контекст, который раньше держал в голове человек.

История проекта и планы — [`docs/HANDOFF.md`](docs/HANDOFF.md).

## Структура репозитория

```
pdf_translator/
├── AGENTS.md              правила для агентов (CLAUDE.md, .hermes.md → сюда)
├── pdft/                  харнесс и общее ядро
│   ├── __main__.py        CLI: inspect / init / build / review
│   ├── job.py             сборка работы из данных, подбор места под текст
│   ├── qa.py              автопроверки
│   ├── segments.py        склейка строк в абзацы
│   ├── tm.py              память переводов
│   ├── blocks.py          инвентарь текстовых блоков
│   ├── overlay.py         удаление и вставка текста, оценка свободного места
│   ├── audit.py diff.py render.py fonts.py
├── jobs/<id>/             работы: job.json, blocks.json, translations.py, NOTES.md (+ локально source.pdf, out/)
├── articles/<slug>/       переводы веб-статей
└── docs/                  правила перевода, техника, глоссарии, история
```

## Что хранится в git

В репозитории — всё, из чего перевод собирается заново: код, `translations.py`, `blocks.json`, глоссарии, заметки и вручную подготовленные картинки. Исходные мануалы и готовые PDF хранятся только локально (`*.pdf`, `out/`, `build/`, `tmp/` в `.gitignore`).

## Ограничения

- Харнесс не видит текст внутри растровых картинок и не перерисовывает их; это делается вручную (как в XM-100).
- Подпись, центрированная по картинке над ней, не распознаётся — выравнивание задаётся явно.
- Перекомпоновки страницы нет: блок растёт только в свободное место рядом.
- Перевод в Arial; родной шрифт оригинала обычно урезан и без кириллицы.

Планы — раздел «Что дальше» в [`docs/harness.md`](docs/harness.md).
